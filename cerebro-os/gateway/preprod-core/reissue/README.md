# Isolated credential lifecycle acceptance
This rehearsal uses two generations of seven Ed25519 identities and two independent HMAC keys. It never reads existing secret values or connects to an existing core service, ledger, or workflow. Only proof signatures, public keys and HMAC tags leave the worker. A new generation must reject old proofs as current while preserving historical public signature verification. The proof is a bounded test of provider-side secret installation and reissuance, not a restoration of all seven core workers, and cannot authorize deployment or dispatch. No routes or cron; EU; no new subscription. Keep old production/PREPROD identities untouched. Do not treat previous generation retention for rollback as cryptographic key destruction. Two fixed rehearsal IDs only. Before activation validate metadata and scope, and preserve exact source and old runtime. Final cleanup disable execution while retaining evidence. If a platform security control denies the operation, stop this route without circumventing it.
