## Reproducción y rollback

1. Verificar que `cerebro-facebook-w24-read-canary-lab-eu` esté sin consumidores antes de adjuntar temporalmente solo el Worker paralelo. Enviar `{"type":"RUN","id":"fb-recheck-20261119-example"}` desde el productor autorizado. Reenviar el mismo ID para idempotencia y enviar `VERIFY` con el mismo ID para consultar las dos filas. El comando `NEGATIVES` comprueba los cinco rechazos con un ID propio. Restaurar la cola retirando únicamente el consumidor añadido. Se verificó el estado final con cero consumidores y productores.
2. Para apagar una capacidad en LAB usar su variable remota `FB_READ_ENABLED` o `UMS_READ_ENABLED`, conservando los secretos y el binding. Restaurar solo la variable cambiada y volver a consultar las filas. La configuración versionada usa ambos interruptores desactivados por defecto para recreaciones.
3. Verificar el recibo real de UMS en `Entregas_LAB`, estado `RESOLVED_LAB`, empresa `fenix`, entorno `LAB`, motor y componente `FACT-OIDC-LAB-E2E-001`, versión `0.1.0`. Actualizar una vez `ums-run-request.json` con el SHA-256 auténtico en la rama de PR #278. El job emite el token real, usa el mismo puente y comprueba decisión, auditoría y cero publicaciones. Si no hay un recibo el Gateway devuelve 409. No aumentar la cuota. La automatización de seguimiento no se creó porque el servicio ya tiene 5/5 tareas activas; se conservaron esas tareas. Si se supera la ventana del Preview, renovar solo la concesión a este despliegue verificando de nuevo las llaves oficiales o dejar cerrado el puente.
